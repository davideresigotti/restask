# Overview
Taskres is a complete, self-hosted system for managing tasks. Everything is kept in sync and optimized to work across all devices. The system is based on Markdown (`.md`) files and VTODO. Every checkbox in the vault is treated as a task and instantly linked to a VTODO task via an autogenerated UID.

# Tools
- **Obsidian**: Dedicated plugin.
- **NeoVim**: Dedicated lua config.
- **Syncthing**: Peer-to-peer file synchronization.
- **Radicale**: Lightweight, self-hosted CalDAV server managing VTODO collections for calendar interoperability.
- **VTODO**: The RFC 5545 open standard for task objects.
- **Tasks.org**: Open-source task management app for Android syncing via CalDAV.
- **Thunderbird**: Desktop CalDAV client for managing tasks alongside the vault.

# UI
The symbols used for priority, date, and other metadata are inspired by [Tasks](https://github.com/obsidian-tasks-group/obsidian-tasks). Suggestions appear when typing at least two letters of a keyword (e.g., `hi` -> high priority, `me` -> medium priority). The list dynamically filters to display only matching options (for example, typing `hi` shows only high and highest priority, hiding low priority).

# Task Structure & Workflow

## Main File: [[test-vault/TODO.md|TODO.md]]
- A single `TODO.md` serves as the central hub.
- It contains both on-the-fly tasks (inbox) and prioritized tasks gathered from across the vault.
- All vault tasks with an assigned priority appear in this file, organized by priority level.

## Vault Tasks & Subtasks: [[test-vault/Home Lab Test.md]], [[test-vault/Project Alpha Test.md]]
- Every checkbox across any file in the vault is recognized as a task.
- When a priority is assigned, the task appears in the main `TODO.md` file. It is not a duplicate copy, but the exact same task synchronized across both files via its UID.
- Tasks without an assigned priority remain solely in their source file (e.g., notes, ideas).

## Completion Behaviour
- Once a task is checked off, it disappears from the active list and is moved under a `### Done` heading in its source file (or in `TODO.md` for on-the-fly tasks), marked with completion date syntax like `✅ 2026-09-19`.
- Tasks in the `### Done` section follow a newest-on-top sort order. If a task is accidentally checked, it can easily be recovered since it appears at the very top.

# Lists & Routing

**Local-only by default**: a note participates in syncing only when explicitly routed. Unrouted notes are never read (beyond frontmatter), never parsed, never modified, and never synced.

- **Route a single note** — frontmatter `restask-list: University` sends that note's tasks to list `University`.
- **Route a whole folder** — a note carrying `restask-list-root: Home Lab` becomes that folder's *root note* and declares the list for the whole directory, recursively. The nearest enclosing root wins; deeper roots shadow shallower ones.
- A note may carry both markers: `restask-list` wins for the file, `restask-list-root` still declares the folder.
- The `TODO.md` inbox is engine-managed and routes to the **Inbox** list.
- A list maps to a Radicale collection via its slug (`Home Lab` → `home-lab` → `http://<radicale-host>:5232/<user>/home-lab/`); the collection is created on first push (`caldav.allow_create_lists`) or bound to an existing one (e.g. `University` → the existing `university` calendar) during `restask setup`.
- Moving a task between differently-routed notes keeps its UID and **moves** the VTODO between collections.

`restask doctor` verifies the whole chain (markers, shadows, conflicts, bindings) — see [INSTALL.md](INSTALL.md) to install the engine, run the setup wizard, and deploy the daemon on your always-on device (systemd user unit or Docker).

# Architecture
Taskres follows a strict **local-first and offline-first** philosophy. All core task interactions occur directly on local files on each device, while network synchronization happens asynchronously in the background.

## Offline-First
- **Local Vault on Phone**: The entire Markdown vault is stored locally on the mobile device and kept in sync via Syncthing.
- **Immediate Local Mutation**: When a task is checked as done in the mobile app or widget without an internet connection:
  - The local Markdown note on the phone is updated immediately (the checkbox becomes `- [x]`, the completion date `✅ YYYY-MM-DD` is appended, and the task is moved under `### Done`).
  - The corresponding VTODO file in the local `.restask/tasks` cache is updated simultaneously.
  - No network connectivity is required to complete, edit, or capture tasks.

## Synchronization on Reconnection
- **Syncthing Propagation**: When connectivity is restored, Syncthing detects that the local Markdown file on the phone has the newest modification timestamp and automatically syncs it across all other devices (desktop, laptop, home server).
- **CalDAV (Radicale) Synchronization**: The Taskres sync process ensures the self-hosted Radicale CalDAV server receives the updated VTODO state, keeping external calendars and schedulers in sync.

## Bidirectional & Cross-Ecosystem Integration
- **VTODO Standard**: Linking tasks to RFC 5545 VTODO allows interoperability with external calendar applications:
  - Tasks scheduled with `📅 2026-09-19` appear as all-day events.
  - Tasks scheduled with `📅 2026-09-19 17:00` appear at that exact scheduled time.
- **Unique Identification**: Every task across the vault is uniquely linked by its autogenerated UID, preventing duplicates and ensuring clean state reconciliation across devices.

# Real Usage

## Mobile (Android)
- **Tasks.org**: Connects to the self-hosted Radicale CalDAV service to manage and check off tasks.
- **Obsidian App**: Directly accesses and edits the vault notes (such as `TODO.md`).
- **Unified Sync**: Actions performed in Tasks.org and edits made inside Obsidian stay completely synchronized.

## Desktop / PC
- **Obsidian Vault**: View and manage tasks directly within Markdown notes and `TODO.md`.
- **CalDAV Clients (Thunderbird)**: View and interact with tasks in desktop applications like Mozilla Thunderbird, kept in sync with the vault via Radicale and VTODO.
