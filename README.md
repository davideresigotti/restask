# Overview
restask is a complete, self-hosted system for managing tasks. Everything is kept in sync and optimized to work across all devices. The system is based on Markdown (`.md`) files and VTODO. Every checkbox in a routed note is a task, linked to a VTODO on your own CalDAV server via an autogenerated UID.

# Tools
- **Obsidian**: Dedicated plugin.
- **NeoVim**: Dedicated lua config, backed by the `restask` CLI (`restask settle` on every save).
- **Syncthing**: Peer-to-peer file synchronization.
- **Radicale**: Lightweight, self-hosted CalDAV server managing VTODO collections for calendar interoperability.
- **VTODO**: The RFC 5545 open standard for task objects.
- **Tasks.org**: Open-source task management app for Android syncing via CalDAV.
- **Thunderbird**: Desktop CalDAV client for managing tasks alongside the vault.

# UI
The symbols used for priority, date, and other metadata are inspired by [Tasks](https://github.com/obsidian-tasks-group/obsidian-tasks). In Obsidian and in Neovim (with blink.cmp), suggestions appear when typing at least two letters of a keyword in a task line (e.g., `hi` -> high priority, `me` -> medium priority). The list dynamically filters to display only matching options (for example, typing `hi` shows only high and highest priority, hiding low priority).

| Symbol | Meaning | Example |
|---|---|---|
| 🔺 ⏫ 🔼 🔽 ⏬ | priority: highest, high, medium, low, lowest | `- [ ] Renew the certificate ⏫` |
| 📅 | due (date, or date and time) | `📅 2026-09-19`, `📅 2026-09-19 17:00` |
| 🛫 / ⏳ | start / scheduled | `🛫 2026-09-18` |
| 🔁 | repeats | `🔁 every week`, `🔁 every 2 weeks on Monday, Thursday`, `🔁 every month on the 15th`, `🔁 every month on the last Friday`, `🔁 every year`, `… for 5 times`, `… until 2026-12-31` |
| ✅ | completed on | `✅ 2026-09-19` |
| ➕ | created on — optional and not added by default. Type a bare `➕` (in Obsidian: `created`) and restask writes the date: today for a new task, the creation date the server has for an existing one | `➕ 2026-09-17` |
| 🆔 | the task's UID (added automatically; leave it alone — the Obsidian plugin and the Neovim integration keep it out of sight) | `🆔 restask-01jz…` |

# Task Structure & Workflow

## Main File: [[test-vault/TODO.md|TODO.md]]
- A single `TODO.md` serves as the central hub.
- It contains both on-the-fly tasks (inbox) and prioritized tasks gathered from across the vault.
- All vault tasks with an assigned priority appear in this file, organized by priority level.
- On-the-fly tasks without a priority are listed below the priority sections, under `## No Priority`.
- The section a task is in and its priority emoji always agree. A task typed under a priority's heading gets that priority automatically. Moving a task to another section (cut and paste) gives it that section's priority; moving it under `## No Priority` removes it. Changing the priority emoji of a task moves it to that priority's section; removing it moves the task to `## No Priority`.
- `TODO.md` is generated by restask: tasks you add or edit there are kept, any other text is not. restask writes no comment or notice into it: besides the tasks, the file holds only two frontmatter properties, `restask-list` and `restask-render` (leave the second alone — it lets restask tell its own render from your edits).

## Vault Tasks & Subtasks: [[test-vault/Home Lab Test.md]], [[test-vault/Project Alpha Test.md]]
- Every checkbox in a routed note (see *Lists & Routing*) is recognized as a task.
- When a priority is assigned, the task appears in the main `TODO.md` file. It is not a duplicate copy, but the exact same task synchronized across both files via its UID: check it off, reword it or re-prioritize it in either place.
- Tasks without an assigned priority remain solely in their source file (e.g., notes, ideas).
- An indented checkbox is a subtask of the checkbox above it.
- In Obsidian and Neovim, a new line under a `TODO` heading of a routed note — and any new line of `TODO.md` above `Done` — starts with `- [ ] `, ready for the task's text. Press Enter on the empty checkbox in Obsidian (delete it in Neovim) for a line that is no task. A checkbox left without text is not a task: it is not synced until you write one.
- None of this waits for the sync: Obsidian does it when you leave the line, Neovim when you save the note (the task ID, the move under `Done`, the line in `TODO.md`) — on the device, offline, with no daemon running there.

## Completion Behaviour
- Once a task is checked off — in Obsidian, in any editor, or in Tasks.org — it disappears from the active list and is moved under a `### Done` heading in its source file (or in `TODO.md` for on-the-fly tasks), marked with completion date syntax like `✅ 2026-09-19`.
- A repeating task (`🔁 every week`, or a repeat set in Tasks.org — the two are the same thing) is never finished for good: checking it off leaves the finished occurrence under `### Done` and puts the task back in the active list with its next date.
- Tasks in the `### Done` section follow a newest-on-top sort order. If a task is accidentally checked, it can easily be recovered since it appears at the very top: uncheck it and it returns to the active list.

# Lists & Routing

**Local-only by default**: a note participates in syncing only when explicitly routed. Unrouted notes are never read (beyond frontmatter), never parsed, never modified, and never synced.

- **Route a single note** — frontmatter `restask-list: University` sends that note's tasks to list `University`.
- **Route a whole folder** — a note carrying `restask-list-root: Home Lab` becomes that folder's *root note* and declares the list for the whole directory, recursively. The nearest enclosing root wins; deeper roots shadow shallower ones.
- A note may carry both markers: `restask-list` wins for the file, `restask-list-root` still declares the folder.
- The `TODO.md` inbox is engine-managed and routes to the list recorded in `inbox_list` (`restask.toml`, default `inbox`) — the calendar you bind it to during `restask setup`.
- A list maps to a Radicale collection via its slug (`Home Lab` → `home-lab` → `http://<radicale-host>:5232/<user>/home-lab/`); the collection is created on first sync (`caldav.allow_create_lists`). `restask lists` shows every list with its URL.
- A task created in Tasks.org or Thunderbird lands in the list's root note (or its first note), or in `TODO.md` for the inbox list. It stays the task that app created: what you change there afterwards — priority, text, dates, done — changes its line, and the other way round.
- Moving a task between differently-routed notes keeps its UID and **moves** the VTODO between collections.

`restask doctor` verifies the whole chain (config, routing, vault, server) — see [INSTALL.md](INSTALL.md): three commands on your computer. The setup wizard asks for the server's address and your credentials once and installs everything — the plugin in the vault (so the phone gets it too), the command line on the computer, and the daemon on your always-on server over ssh, the one place it runs.

# Architecture
restask follows a strict **local-first and offline-first** philosophy. All core task interactions occur directly on local files on each device, while network synchronization happens asynchronously in the background. The design is described in [ARCHITECTURE.md](ARCHITECTURE.md).

## Offline-First
- **Local Vault on Phone**: The entire Markdown vault is stored locally on the mobile device and kept in sync via Syncthing.
- **Immediate Local Mutation**: When a task is checked as done without an internet connection, the local Markdown note is all that changes (with the plugin: the checkbox becomes `- [x]`, the completion date `✅ YYYY-MM-DD` is added, and the task is moved under `### Done`).
- No network connectivity is required to complete, edit, or capture tasks. Nothing else has to be written on the device: the Markdown file is the task.

## Who does the work, where
What restask does to a note falls in two parts. The *local* part needs nothing but the vault: giving a new task its ID, moving a checked task under `Done`, keeping `TODO.md` and the notes in step. The *server* part is everything that involves Radicale. The local part is done on the device you edit on, at once and offline; only the server part belongs to the daemon.

| Where you edit | Who does the local part | When |
|---|---|---|
| Obsidian (PC, phone) | the restask plugin | when you leave the line; a checkbox at once |
| Neovim (PC) | `restask settle`, run by the Neovim integration | when the note is saved |
| Any other editor, or a file that arrives through the file sync | the daemon on the sync node (the fallback) | at its next pass, then back through the file sync |
| The sync node itself | the same daemon | every pass |

- **`restask settle`** is the engine's local part as a command: it reads the vault, registers, repairs and files the tasks, refreshes `TODO.md`, and stops. It never contacts Radicale, needs no configuration of the machine, and works with the network off. Run it by hand in a vault after editing with any other tool: `restask settle`.
- **A PC with both Obsidian and Neovim** runs no daemon. The same vault folder is open in both; whichever you edit in does the work, and the other one picks the files up as changed on disk. Both follow the same rules, so it does not matter which got there first.
- **The fallback is the daemon.** An edit made with neither — another editor, a script, `settle = false` in Neovim, the plugin switched off — is not lost and not wrong, only later: the file travels to the sync node, the daemon does the same local part there, and the result comes back with the file sync.
- **On the server nothing changes.** The sync node runs the one daemon, as before. Each of its passes starts with exactly what `restask settle` does — the same code — and then goes on to Radicale. A vault that a device already settled gives it nothing to write in the notes; it only pushes and pulls.

## Synchronization on Reconnection
- **Syncthing Propagation**: When connectivity is restored, Syncthing carries the changed notes to the other devices (desktop, laptop, home server).
- **CalDAV (Radicale) Synchronization**: The restask daemon on the always-on device reads the vault and the server and makes them agree, keeping external calendars and task apps in sync. It asks the server for changes every two seconds, so a task added, changed or deleted in Tasks.org is in the sync node's vault moments after Tasks.org has uploaded it; from there the file sync carries it to the other devices (with Syncthing, after the folder's watcher delay — see INSTALL, *Latency*).

## How changes are reconciled
- restask remembers, per task, what the vault and the server last agreed on. A change made on one side only simply wins — so completing a task in Tasks.org while rewording it in Obsidian keeps both.
- Only when the *same field* was changed on both sides is there a conflict; then the newer change wins, and the vault wins when they are less than two minutes apart.
- Deleting a task line deletes it on the server; deleting it in Tasks.org removes the line. Deleting a note task's line in TODO.md deletes the task in its note too: it is the same task. A task line that is in your vault is never removed for any other reason.
- Notes, reminders, tags and recurrence that other apps store on a task are preserved.

## Bidirectional & Cross-Ecosystem Integration
- **VTODO Standard**: Linking tasks to RFC 5545 VTODO allows interoperability with external calendar applications:
  - Tasks scheduled with `📅 2026-09-19` appear as all-day items.
  - Tasks scheduled with `📅 2026-09-19 17:00` appear at that exact scheduled time.
- **Unique Identification**: Every task across the vault is uniquely linked by its autogenerated UID, preventing duplicates and ensuring clean state reconciliation across devices. Copying a task line creates a new task with its own UID.

# Real Usage

## Mobile (Android)
- **Tasks.org**: Connects to the self-hosted Radicale CalDAV service to manage and check off tasks.
- **Obsidian App**: Directly accesses and edits the vault notes (such as `TODO.md`).
- **Unified Sync**: Actions performed in Tasks.org and edits made inside Obsidian stay completely synchronized.

## Desktop / PC
- **Obsidian Vault**: View and manage tasks directly within Markdown notes and `TODO.md`.
- **NeoVim**: saving a note settles it on the spot (`restask settle`: ID, `Done`, `TODO.md`); `<leader>td` toggles the task under the cursor, `<leader>ta` captures one; the `🆔` tokens are concealed.
- **Both on one PC**: Obsidian and Neovim work on the same vault folder with no daemon on the PC; the daemon on the server is the fallback for everything else.
- **CalDAV Clients (Thunderbird)**: View and interact with tasks in desktop applications like Mozilla Thunderbird, kept in sync with the vault via Radicale and VTODO.
