# Overview
restask is a complete, self-hosted system for managing tasks. Everything is kept in sync and optimized to work across all devices. The system is based on Markdown (`.md`) files and VTODO. Every checkbox in a routed note is a task, linked to a VTODO on your own CalDAV server via an autogenerated UID.

# Tools
- **Obsidian**: Dedicated plugin.
- **NeoVim**: Dedicated lua config.
- **Syncthing**: Peer-to-peer file synchronization.
- **Radicale**: Lightweight, self-hosted CalDAV server managing VTODO collections for calendar interoperability.
- **VTODO**: The RFC 5545 open standard for task objects.
- **Tasks.org**: Open-source task management app for Android syncing via CalDAV.
- **Thunderbird**: Desktop CalDAV client for managing tasks alongside the vault.

# UI
The symbols used for priority, date, and other metadata are inspired by [Tasks](https://github.com/obsidian-tasks-group/obsidian-tasks). In Obsidian, suggestions appear when typing at least two letters of a keyword in a task line (e.g., `hi` -> high priority, `me` -> medium priority). The list dynamically filters to display only matching options (for example, typing `hi` shows only high and highest priority, hiding low priority).

| Symbol | Meaning | Example |
|---|---|---|
| 🔺 ⏫ 🔼 🔽 ⏬ | priority: highest, high, medium, low, lowest | `- [ ] Renew the certificate ⏫` |
| 📅 | due (date, or date and time) | `📅 2026-09-19`, `📅 2026-09-19 17:00` |
| 🛫 / ⏳ | start / scheduled | `🛫 2026-09-18` |
| ✅ | completed on | `✅ 2026-09-19` |
| ➕ | created on (added automatically) | `➕ 2026-09-17` |
| 🆔 | the task's UID (added automatically; leave it alone) | `🆔 restask-01jz…` |

# Task Structure & Workflow

## Main File: [[test-vault/TODO.md|TODO.md]]
- A single `TODO.md` serves as the central hub.
- It contains both on-the-fly tasks (inbox) and prioritized tasks gathered from across the vault.
- All vault tasks with an assigned priority appear in this file, organized by priority level.
- `TODO.md` is generated by restask: tasks you add or edit there are kept, any other text is not.

## Vault Tasks & Subtasks: [[test-vault/Home Lab Test.md]], [[test-vault/Project Alpha Test.md]]
- Every checkbox in a routed note (see *Lists & Routing*) is recognized as a task.
- When a priority is assigned, the task appears in the main `TODO.md` file. It is not a duplicate copy, but the exact same task synchronized across both files via its UID: check it off, reword it or re-prioritize it in either place.
- Tasks without an assigned priority remain solely in their source file (e.g., notes, ideas).
- An indented checkbox is a subtask of the checkbox above it.

## Completion Behaviour
- Once a task is checked off — in Obsidian, in any editor, or in Tasks.org — it disappears from the active list and is moved under a `### Done` heading in its source file (or in `TODO.md` for on-the-fly tasks), marked with completion date syntax like `✅ 2026-09-19`.
- Tasks in the `### Done` section follow a newest-on-top sort order. If a task is accidentally checked, it can easily be recovered since it appears at the very top: uncheck it and it returns to the active list.

# Lists & Routing

**Local-only by default**: a note participates in syncing only when explicitly routed. Unrouted notes are never read (beyond frontmatter), never parsed, never modified, and never synced.

- **Route a single note** — frontmatter `restask-list: University` sends that note's tasks to list `University`.
- **Route a whole folder** — a note carrying `restask-list-root: Home Lab` becomes that folder's *root note* and declares the list for the whole directory, recursively. The nearest enclosing root wins; deeper roots shadow shallower ones.
- A note may carry both markers: `restask-list` wins for the file, `restask-list-root` still declares the folder.
- The `TODO.md` inbox is engine-managed and routes to the list recorded in `inbox_list` (`restask.toml`, default `inbox`) — the calendar you bind it to during `restask setup`.
- A list maps to a Radicale collection via its slug (`Home Lab` → `home-lab` → `http://<radicale-host>:5232/<user>/home-lab/`); the collection is created on first sync (`caldav.allow_create_lists`). `restask lists` shows every list with its URL.
- A task created in Tasks.org or Thunderbird lands in the list's root note (or its first note), or in `TODO.md` for the inbox list.
- Moving a task between differently-routed notes keeps its UID and **moves** the VTODO between collections.

`restask doctor` verifies the whole chain (config, routing, vault, server) — see [INSTALL.md](INSTALL.md) to install the engine, run the setup wizard, and deploy the daemon on your always-on device (systemd user unit or Docker).

# Architecture
restask follows a strict **local-first and offline-first** philosophy. All core task interactions occur directly on local files on each device, while network synchronization happens asynchronously in the background. The design is described in [ARCHITECTURE.md](ARCHITECTURE.md).

## Offline-First
- **Local Vault on Phone**: The entire Markdown vault is stored locally on the mobile device and kept in sync via Syncthing.
- **Immediate Local Mutation**: When a task is checked as done without an internet connection, the local Markdown note is all that changes (with the plugin: the checkbox becomes `- [x]`, the completion date `✅ YYYY-MM-DD` is added, and the task is moved under `### Done`).
- No network connectivity is required to complete, edit, or capture tasks. Nothing else has to be written on the device: the Markdown file is the task.

## Synchronization on Reconnection
- **Syncthing Propagation**: When connectivity is restored, Syncthing carries the changed notes to the other devices (desktop, laptop, home server).
- **CalDAV (Radicale) Synchronization**: The restask daemon on the always-on device reads the vault and the server and makes them agree, keeping external calendars and task apps in sync.

## How changes are reconciled
- restask remembers, per task, what the vault and the server last agreed on. A change made on one side only simply wins — so completing a task in Tasks.org while rewording it in Obsidian keeps both.
- Only when the *same field* was changed on both sides is there a conflict; then the newer change wins, and the vault wins when they are less than two minutes apart.
- Deleting a task line deletes it on the server; deleting it in Tasks.org removes the line. A task line that is in your vault is never removed for any other reason.
- Notes, reminders, tags and recurrence that other apps store on a task are preserved.

## Bidirectional & Cross-Ecosystem Integration
- **VTODO Standard**: Linking tasks to RFC 5545 VTODO allows interoperability with external calendar applications:
  - Tasks scheduled with `📅 2026-09-19` appear as all-day items.
  - Tasks scheduled with `📅 2026-09-19 17:00` appear at that exact scheduled time.
- **Unique Identification**: Every task across the vault is uniquely linked by its autogenerated UID, preventing duplicates and ensuring clean state reconciliation across devices. Copying a task line creates a new task with its own UID.

# Real Usage

## Mobile (Android)
- **Tasks.org**: Connects to the self-hosted Radicale CalDAV service to manage and check off tasks.
- **Obsidian App**: Directly accesses and edits the vault notes (such as `TODO.md`).
- **Unified Sync**: Actions performed in Tasks.org and edits made inside Obsidian stay completely synchronized.

## Desktop / PC
- **Obsidian Vault**: View and manage tasks directly within Markdown notes and `TODO.md`.
- **NeoVim**: `<leader>td` toggles the task under the cursor, `<leader>ta` captures one.
- **CalDAV Clients (Thunderbird)**: View and interact with tasks in desktop applications like Mozilla Thunderbird, kept in sync with the vault via Radicale and VTODO.
